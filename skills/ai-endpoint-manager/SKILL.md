# AI Endpoint Manager

## 使命

检查用户当前 AI 访问能力，核对可用模型、账号状态、接口和本机 CLI 环境。

本 Skill 属于 Haruka Lab 的「开发工程」流程。它应在当前环境中完成工作并留下可验证产物；如果缺少工具或权限，要明确说明可完成的部分与阻塞点。

## 何时使用

- 开发、调试、部署网站或自动化工具。
- 处理 CLI、浏览器、API、服务器和 GitHub 工作流。
- 上线前做构建、冒烟、真实页面和回归验证。

## 需要的输入

- 仓库、文件、报错、目标行为或可复现步骤。
- 运行环境、版本、部署平台和项目约定。
- 允许修改的范围以及必须保持不变的接口。

只询问会实质改变方案的缺失信息。能够从文件、上下文或现有页面安全确认的内容，先自行核对。

## 工作方法

1. 先读取项目约定、目录结构和当前变更，避免覆盖用户已有工作。
2. 复现问题或建立当前基线，用代码和运行结果定位原因。
3. 实施范围最小但完整的修改，同时处理相关边界、错误状态和兼容性。
4. 运行与风险相称的静态检查、测试、构建或真实交互验证。
5. 复查差异，确认没有秘密信息、临时文件和无关改动。

## 交付物

- 可审阅的代码或配置变更。
- 测试、构建或复现证据。
- 风险、兼容性与部署说明。

## 边界与安全

- 不虚构来源、数据、运行结果、文件、账号状态或外部操作。
- 尊重用户指定的语言、品牌、格式、工具和修改范围。
- 涉及发送、发布、购买、删除、权限或不可逆变更时，动作前确认。
- 先检查工具是否可用、账号是否已授权；不声称执行了没有实际验证的外部动作。

## 验收清单

- 修改解决根因并保持既有行为。
- 命令、路径、版本和配置可在目标环境使用。
- 失败路径与回滚方式已考虑。
- 交付物与最初目标一致，名称、链接、命令和文件路径可用。
- 清楚标注未验证项、限制和最有价值的下一步。
